小さなUSBマクロキーボードにキー設定を書き込むmacOSアプリです。ノブが1つだけのものからキーが21個あるものまで、ノブは最大4つという構成で売られているキーボードが対象です。キーとノブの操作（反時計回りに回す・押す・時計回りに回す）ごとに、レイヤー1–3にキー入力・マルチメディアキー・マウス操作を割り当て、キーボードのライティングも設定します。

| キーボード | 配列 | 読み込み | 遅延 | ライティング | 実機での確認 |
|---|---|---|---|---|---|
| `1189:8890` | ユーザーが決める：キー（最大12個）・1列のキー数・ノブ（最大2個） | 不可 | なし | モード3つ | 済み（キー6個・ノブ1つ） |
| ベンダー`1189`または`514C`、製品`8840`・`8842`・`8830`–`8833`・`8850`（と`514C:8851`）、新しいファームウェア | キーボードが知らせるとおり（26種類） | 接続時にすぐ | 入力ごと | モード1つとキー1–16の色 | 未確認 |
| 同じキーボード、旧ファームウェア | キーボードが知らせるとおり | 要求したとき | キーごとに1つ | 色とモード | 未確認 |
| 同じキーボードで、種類を知らせないもの | ユーザーが選ぶ（26種類） | 不可 | なし | 色とモード | 未確認 |

`1189:8890`はメーカーのWindows用設定ツール「MINI KeyBoard」が扱うキーボードで、それ以外はメーカーのマルチプラットフォームアプリ「MINI_KEYBOARD」が探すキーボードです。このアプリは両方のツールのコマンドを使います。2つ目のグループのキーボードはたいてい、キーとノブの数やファームウェアの種類を知らせてくるので、メーカーのアプリが描く配列をそのまま描きます。知らせてこないキーボードには、それらの配列の中からユーザーが選んだものを使います。`1189:8890`はメーカーのアプリが知らないキーボードで、専用のツールも形を描かないため、実際の形はわかりません。そこで、キーとノブの数と1列のキー数を決めると、アプリがそのとおりに整った形で描きます。

アプリは13の言語で表示されます：英語・韓国語・日本語・中国語（簡体字・繁体字）・ドイツ語・スペイン語・フランス語・イタリア語・ポルトガル語（ブラジル）・ポーランド語・インドネシア語・ベトナム語。macOSの言語設定に従い、それ以外の言語では英語で表示されます。

このリポジトリのソースはMITライセンスです。配布しているアプリの一部（名前とアイコン）は、このソースに含まれていません。冒頭のアイコンは紹介のために置いた画像で、MITライセンスの対象外です。このリポジトリからビルドしたアプリにも含まれません。

## ダウンロード

署名と公証を済ませたアプリは[Releases](https://github.com/hobbyworker/MINIKeyboardApple/releases)にあります。`MINIKeyboard-<バージョン>.dmg`を開き、MINIKeyboardを「アプリケーション」フォルダにドラッグします。アプリは自動でアップデートを確認します（設定 ▸ 一般）。アプリメニューから手動で確認することもできます（**アップデートを確認…**）。

## 動作環境

- macOS 14.0（Sonoma）以降
- `1189:8890`には、許可が必要なアクセス権はありません。アプリはこのキーボードの設定用インターフェイスにUSBで直接書き込み、入力した内容は読み取りません。
- それ以外のキーボードは、メーカーのアプリと同じく1つ目のUSBインターフェイスで設定します。macOSがそのインターフェイスをキーボードとみなす場合、入力監視を許可したアプリにしかそれを開かせません。許可されるまでは、アプリがその旨を知らせ、「プライバシーとセキュリティ」を開けるようにします。

## ビルド

```sh
make build          # Xcodeでビルド（警告はエラー扱い）
make package-test   # パッケージのテスト — アプリは起動しない
make test           # アプリのテスト — アプリがテストホスト
make check          # プロジェクトファイルにチームIDが入っていたら失敗
```

Xcode 27.2でビルドとテストを確認しています。

署名と識別情報の設定はリポジトリにありません。最初にビルドする前にサンプルをコピーし、自分のApple DeveloperチームID・アプリ名・バンドルIDを記入してください。このファイルがないと、ビルドは`Unable to open base configuration reference file ... Signing.xcconfig`で止まります。

```sh
cp Signing.xcconfig.example Signing.xcconfig
```

アイコン名は入れなくてもかまいません。アイコンの画像がなければ、アプリはシステムの汎用アイコンでビルドされます。

アップデートも任意です。アプリは[Sparkle](https://sparkle-project.org)をSwift Package Managerでリンクしますが（初回のビルドでXcodeが取得します）、`Signing.xcconfig`にフィード（`BRAND_FEED_URL`）とそのEdDSA公開鍵（`BRAND_FEED_PUBLIC_KEY`）の両方があるときだけアップデートを確認します。ない場合、アップデートの項目はどこにも表示されません。

Xcodeでプロジェクトを開くと、共有スキーム（`MINIKeyboard.xcodeproj/xcshareddata/xcschemes/`）内の製品名がXcodeによって自分のものに書き換えられます。これは正常な動作で、コミットする必要はありません。

アプリのテストのホストはアプリ自身です。テスト中、アプリはいつもどおりキーボードを探して接続します。パッケージのテストはフェイクとシミュレートしたキーボードを使い、キーボードを開きません。

Debugビルドには、対象のキーボードがなくてもアプリを試せる**シミュレータ**メニューがあります。レポートIDごとの`1189:8890`、両方のファームウェアのすべての配列、種類を知らせないキーボードのいずれかを選ぶと、アプリは接続されているかのように同じコマンドで動作し、USBには何も送りません。**ウインドウ ▸ デバイスログ**で、書き込んだレポートと受け取った応答をすべて確認できます。

## 使い方

1. キーボードをUSBで接続します。アプリがキーボードを見つけ、2つ目のグループのキーボードには種類を問い合わせます。新しいファームウェアであれば、すぐに設定を読み込みます。
2. 形を知らせないキーボードでは、最初に配列（メーカーのアプリの配列のいずれか。`1189:8890`ではキー・1列のキー・ノブの数）と、手前に置いた向きを決めます。アプリはUSB IDごとにこれを記憶します。あとから**形…**、**回転**（⌘T）で変更できます。形を知らせたキーボードは回転だけができます。
3. レイヤーを選び、キーボードの図でキーやノブの操作を選びます。
4. 操作を割り当てます。
   - **キー**：修飾キー（⌃ ⌥ ⇧ ⌘と右側のもの）を押したままキーをクリックします。クリックするたびに入力が1つずつ追加されます。**修飾キーのみ**は、そのキーを修飾キーにします。**QWERTY**はキーをフルサイズキーボードのように、**ABC**はグループごとに並べます。クリックできるのは、キーボードが受け付けるキーだけです。
   - **マルチメディア**・**マウス**：キーにあった操作を置き換えます。
   - **LED**：レイヤーのライティングです。新しいファームウェアでは、キー1–16のいずれかを選んで色を付けます。
   - **遅延**：遅延を記憶するファームウェアで使えます。
5. **保存**（⌘S）で変更を書き込みます。**読み込む**（⌘R）は、読み込みに対応したキーボードから現在の設定を取得します。

**設定**（⌘,）では、表示言語（13言語のいずれか、またはシステムの言語）とライト・ダークを選び、「情報」でバージョンとオープンソースライセンスを確認できます。アップデートのフィードがある場合（上記）、アプリメニューの「設定…」のすぐ下に **アップデートを確認…** があります。

## 構成

ルールはローカルのSwiftパッケージにあります。3つのモジュールの依存関係は内側にだけ向かい、外側に手を伸ばすレイヤーはコンパイルできません。

```
Packages/MINIKeyboardKit/
├── Sources/Domain/        キーボード・操作・配列のコントロール・キーボードごとに保持できるもの、リポジトリプロトコル、ユースケース（Foundationのみ）
├── Sources/DataLayer/     キーボードごとのコマンドとコントロールの番号、キーボードの検出とUSB（IOUSBHost）・HID（IOHIDDevice）での書き込み、シミュレータのキーボード
├── Sources/Presentation/  ビューモデルと画面が描く値 — 配列の図形、キー・色の表（Observation、SwiftUIなし）
└── Tests/                 Swift Testing — すべてのコマンドのバイト列、配列、編集、エディタ
MINIKeyboard/
├── App/                   アプリのエントリポイント・メニュー、組み立て（composition root — DomainとDataLayerを知る唯一のファイル）、アップデート（Sparkle）、ライセンス
├── Views/                 SwiftUI（Presentationだけをimport）— 置かれたとおりのキーボード、操作ページ、配列シート、デバイスログ、Settings/
├── Resources/Licenses/    設定 ▸ 情報に表示するオープンソースライセンス
└── Localizable.xcstrings  en（原文）・de・es・fr・id・it・ja・ko・pl・pt-BR・vi・zh-Hans・zh-Hant
MINIKeyboard-Info.plist    Xcodeが生成できないInfo.plistのキー — Sparkleのフィードと鍵、著作権表示
MINIKeyboardTests/         アップデートのスイッチ・ライセンス・アプリメニュー
```

Swift 6で警告ゼロが基準です。警告は抑制せずに修正します。

## 制限事項

- 書き込みはこれまで1台のキーボード、キー6個・ノブ1つの`1189:8890`でしか確認していません。このキーボードはレイヤーが1つしかないため、どのレイヤーに書き込んでも同じところに入ります。それ以外のキーボードには、メーカーのアプリと同じように書き込みます。テストでバイト列を守っていますが、実機ではまだ1台も確認できていません。
- `1189:8890`と種類を知らせないキーボードは現在の設定を知らせないため、アプリで設定したものだけが表示されます。
- 一度に扱えるキーボードは1台です。複数接続すると、最初に見つけたもの（`1189:8890`が優先）を使います。
- マウスの移動とドラッグには対応していません。
